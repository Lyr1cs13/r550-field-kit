# 故障恢复速查

| 现象 | 先做 | 恢复 |
|---|---|---|
| 低椅脚、线缆卡住，轮子转但车不走 | `./kit hold`；停止地图写入 | 移开物体或加禁区；确认车已脱困，重新定位后继续 |
| 地图位置与实车不符、雷达整体错位 | 停车；不要继续按错误坐标行驶 | 导航模式设置实际位置；不确定时放回原桩后初始化 |
| 建图已出现重影、斜墙或假通道 | `./kit hold` | 放回原桩，停止程序，从最近好检查点恢复并重扫该段 |
| 贴墙但没撞，导航不动 | 看车身足迹和实时近物，不只看圆形膨胀颜色 | 选旁边宽通道，或给宽处中间点绕行；完整足迹仍被占用时先脱困 |
| 直线左右摆头、终点过冲 | 保留速度与角速度日志 | 先查定位与时间，再查底盘响应；降低速度、提前减速，调整前视与角加速度，不只放宽容差 |
| 明明到位置，却反向调角 | 分辨路径末端切线和最终点位朝向 | 清理末端短折线；保留“位置→朝向”两阶段；点位留出转身空间 |
| 右后固定出现一个近点 | 检查同雷达高度的天线、支架和线束 | 优先改安装位置；确认自车回波后才启用小范围体积过滤 |
| 回到桩边、未充电就停 | 核对触点与充电灯 | 点主动回充重走原生对接；不把“到桩边”当作充电成功 |
| 已贴合但仍空转 | 停止任务；必要时手柄急停 | 核对电流、红外、轮速时间戳和看门狗；不反复重置里程保护预算 |
| 手动搬回桩，地图箭头没更新 | 实车停稳 | 导航面板“车在桩位：初始化”；建图恢复好检查点，不只发布 AMCL 初始位姿 |
| Navigation active 但不走 | 看任务状态、目标结果和 `/cmd_vel` | active 只是服务已激活；确认有任务、未暂停，目标及通路没有被占用 |
| SSH 正常、RViz 雷达断续 | 两端同域、同时间、DDS 绑定车网 | 看 `/scan`、`/odom` 频率与 TF；处理无线桥接/ARP，再调导航 |
| WS63 心跳丢失 | 看 USB 枚举、线缆和固定基站供电 | 使用“重新连接”；复用当前固件。Windows 烧录时避免被 VMware 抢走 USB |
| RSSI 后半段越来越稀疏 | 导出 raw.csv 看 reason | `serial_backlog` 查校时和积压；`pose_stale` 查定位帧；保留剔除记录，不用目标坐标补造实测 |

## 碰到低障碍后的固定流程

1. `./kit hold`，确认轮停。
2. 低于二维雷达扫描面的物体，用现场处理或禁区绕开。
3. 导航模式：在当前位置重新设置定位；无法可靠确认时，手动回原桩、同方向贴合，再初始化。
4. 建图模式：若图已坏，停止程序、恢复好检查点；若图未坏且扫描可匹配，先验证对齐，再恢复地图写入。
5. 空转那一段的轮程不当作真实位移；不要在定位错误时靠清空代价图继续顶。

## 定位与底图分别看

激光扫描是实时测量；地图中的扫描位置依赖 TF、里程计、IMU 和激光匹配。雷达本身正常，定位错了也会显示成“雷达滑走”。

- 静止仍持续转：检查 `/imu/data_filtered`、EKF 输入和重复 TF 发布者。
- 空转后才错：先恢复定位锚点，再检查是否损坏 SLAM 图。
- 时间或数据中断：先修通信，不用调膨胀半径掩盖。

只读扫描一致性检查：`python3 rrt_mapping/scan_alignment_monitor.py`。结果在 `state/diagnostics/`。它辅助检查局部墙线，现场车头方向也要对应。

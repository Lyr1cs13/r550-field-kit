# 固定朝向巡航与异常恢复

本页记录ROS 2 Humble巡航的控制逻辑及软件与实车的验收方法。

## 行驶和到点

普通停靠使用 4 cm、4°。固定基站 RSSI 定点采集使用 12 cm、3°，每条样本绑定实际地图位姿。到点日志记录耗时、控制器和修正次数。

直线段通过 Nav2 实时路径检查后，使用前视距离 0.80 m 的 FixedHeading。倒车沿原朝向输出负线速度。进入位置门限即停车复核，再处理朝向。需要绕障或车头与路段不一致时，由 Nav2 规划绕行。

双车定点采集使用 5.5 cm、4°。近点直线候选先检查整段净空，再决定前进或倒车。位置达标后，末端只执行零线速度的原地转向。调度重试使用同一到点门限，先复用已停稳且位姿达标的车辆，只为仍未到点的一车重新规划。

四驱差速车不能横移。环线上与统一车头方向垂直的一边，车辆仍需改变行驶朝向，然后在采集点恢复统一朝向。软件不能保证这一边也像平行边一样无转向连续通过。如果采集布局允许，优先把多数点位排列在与测量朝向平行的长直线上，以前进和倒车连接，减少横向换边次数。

双走廊场景可在场景目录中加入 `corridor_route.json`。填写 `schema: 1`、当前 `map_id`、两条 `lanes`、一到两条 `links` 和 `clearance_m`。每条 `lanes` 用 `[x, y_min, y_max]` 描述地图上的中线，`links` 填两线之间已核验的横穿位置 `y`。切换场景时校验地图、禁区与净空。车端优先沿中线前进、倒车或转弯，参考线受阻时按实时地图重新规划原目标，双车重新核对通行预约。到点后连续复核实测位置与朝向。双车采集返程时，桩前接管点位于走廊中线的车也使用这条策略。替代路线在桩外须满足走廊净空，进入接管区后由厂家红外完成对接。

有净空时，从实测姿态沿相切圆弧接入走廊。停靠点旁的小幅横偏可短距离退出，再沿平顺曲线进入。实车用不同的直线和曲线跟踪参数。停靠判定仍使用点位规定的位置和朝向。走廊场景可配置至少 0.25 m 的直行离桩距离，离桩后须确认触点解除、轮停及转向净空。

双车定点的参考线和原生重规划都检查场景净空。走廊入口临时受阻时，先试另一条有净空的连接线。车已经停在规划余量内侧时，可沿当前朝向选取一段前进或倒车线路，复核车身扫掠、实时雷达和双车间距，并逐步拉开与障碍的距离。回到可转向的位置后再接入走廊。

车在横向连接走廊中途停车后，从当前实测位置继续前进或倒车到目标走廊。偏离中线时先检查一小段回到中线的路径，全段通过净空检查后再申请双车通行。

走廊直线跟踪使用 0.48 m 前视，降低小横偏引起的往复转向。曲线跟踪和停稳后的朝向校准使用各自的参数。排查直线摆头时，对照路径、导航角速度、发到底盘的角速度和陀螺仪读数。

回充使用 Nav2 到达已标定的桩前点，然后由厂家红外完成对接。桩旁的通行根据车身轨迹与桩体轮廓检查。实测触点处未通电时，可以低速向前退出再对接。

如静止转向后的起步阶段有可重复的额外偏转，可按车在 `config/vehicle.yaml` 的 `corridor_drive` 设置 `forward_rollout_yaw_deg` 与 `reverse_rollout_yaw_deg`。分别记录左右转向后车辆刚起步的陀螺仪、里程计和实际位姿再标定。默认值为 0°。仅走廊内的行前对准使用这项标定，停靠朝向依据停稳后的实测位姿验收。

网页点位区增加“统一朝向”和“载入未完成点位”。应用朝向只保存点位，不发车。生成等间距点位时，可以使用明确画出的通道折线：

```bash
python3 tools/fixed_route.py --scene scenes/现场场景 \
  --vertices 通道拐点.json --count 50 --heading-deg 0 --wait 3 \
  --output 统一朝向50点.json
```

通道拐点文件为`[[x1,y1],[x2,y2],...]`。只有末尾明确重复第一个拐点才闭环，避免自动跨越门槛。工具检查整条折线的静态通行空间，并写入map_id。导入面板后仍由实时导航处理障碍。这里不预填未经现场确认的北区坐标。

## 遇到人、受阻和定位异常

可绕行的通路交给Nav2规划。普通点位、离桩和回桩途中遇到临时阻塞时保留原目标，停车后逐步延长重试间隔，最长10秒。不会因为一次导航失败直接跳到下一采集点。永久堵路或低于雷达扫描面的物体不能承诺自动通过。

速度链为控制器→速度平滑→碰撞监视→最终速度门控→底盘。门控只有在导航任务、定位和传感器就绪时接受运动许可。控制指令或许可心跳超过0.3秒、有效雷达超过0.4秒未更新时停止输出运动速度。Nav2 Humble 1.1.15的断流行为经原生测试发现不足，因此雷达新鲜度检查独立放在最终门控中。门控节点自身也有心跳，缺失时任务暂停。厂家STM32红外贴合仍由原生硬件模式执行。退出厂家回充或监督心跳超过 0.5 秒未更新时，速度门控连续下发停止回充和零速指令。取消运动后持续输出零速。扫掠区有实时净空时，门控识别同向、短时且逐渐减速的停车余量。直线余量随停车前速度变化，0.08 m/s 及以下为 3.5 cm，上限为 6 cm。持续位移、反向运动或余速超时仍可触发停车锁。

局部与全局软膨胀半径分别为 0.36 m 和 0.42 m。普通导航线速上限为 0.12 m/s，加速上限为 0.20 m/s²。雷达发现障碍进入当前行驶弧线前方 0.48 m 范围时，逐步压低速度。旁侧墙线仍参与规划代价。近身障碍进入车身保护区时停车。

近障停车后可执行约 20 cm 的低速直退。短退要求定位有效、车尾和退出通道净空，速度上限 0.05 m/s。净空消失、位置偏离、里程无有效进展或许可中断时停车。双车采集若在同一位姿三次收到 Nav2 行驶中止，停止重试并复核短退。确实退出、重规划后仍受阻且车尾净空时，同一处可再短退一段。新起点优先重新核对走廊中线。`config/vehicle.yaml` 可记录该车确认过的天线回波坐标，原始雷达话题保留。

轮式里程计报告前进而连续雷达帧仍匹配在原位置时，控制链停车并保留当前点。进入原地转向时重置平移检查的参考帧，转向继续使用碰撞检查和实际角速度反馈。停稳后请求 AMCL 无运动更新。恢复要求匹配到空转前的雷达定位位置，并通过墙线、协方差和连续稳定检查。短暂遮挡或缺少能辨别运动方向的墙线时，系统继续用避障与导航进度检查。首次复核通过可以重规划。同一处再次空转时保持停车，处理现场后重新定位。

重复走廊可能出现错误但自洽的定位，二维雷达也可能看不到低障碍。这套一致性检查不能证明全局位置绝对正确。实车若确有空转或低障碍碰撞，需要检查雷达覆盖、安装外形、轮速和IMU；必要的近地测距或接触传感器无法靠软件模拟补足。

## 回充、续作和重启

导航服务启动或重连时，车端每 2 秒查询节点状态。单次查询超过 4 秒就丢弃旧请求并重新检查。面板使用各节点最近回复的状态判断是否就绪。

低电量续采由[config/endurance.yaml](../config/endurance.yaml)配置。按车设置低电量阈值、恢复电压、最短充电时间及电压保持时间。设置 `repeat_only: true` 时，勾选「循环巡航」启用续采。普通任务在低电量时结束并回充。

启用后，保留已写盘数据和下一待测点。充电、停稳、桩位校准和电压均满足条件后，从保留的点位继续。固定基站定点模式还会在桩上等待接收恢复。手动暂停或停止会撤销自动续作。先在现场跑通一次低电回桩、充电和续采，再延长试运行时长。

每次前往点位前原子保存`mission_checkpoint.json`。程序重启后不自动发车；可在面板载入剩余点位，重新核对采集模式和定位再开始。未确认完成的当前站可能重新采集，不能将中断记录当成已完成。主动停止明确取消任务并清除续作记录。

厂家红外模式停止后，速度门控持续发零速、关闭红外控制，并等新鲜轮速连续停稳 0.2 秒。短余动自行消失时继续原回充流程。反馈仍有明显运动、位移达到 5 厘米，或低速余动持续 1.5 秒时保留停车锁定。普通导航中收到充电接触反馈时立即截断速度，单独的接触信号不再写入持久锁。无电流且持续停稳 6 秒后，车端检查桩位和净空，允许一次受保护的退出和重新对接。

普通行驶中断时同样立即输出零速。上次线速命令与当前余动同向，轮速不超过 0.055 m/s、刹停位移小于 3.5 cm 且雷达确认净空时，允许在最近一次速度命令后 1.2 秒内自然刹停。

正常刹停判定仍报余动时，车端会复核小幅平移和转动。复核限于刚执行过运动命令、雷达和桩位净空、轮速不超过 0.05 m/s 和 0.16 rad/s、累计行程小于 4.5 cm 且累计转角小于 8° 的情况。复核期间持续发零速。余动须在 1.5 秒内降至静止范围，连续 0.3 秒的新轮速帧确认停稳后，才接受新的行驶许可。超限、明显反向或出现障碍时锁定底盘。

## 可复现测试

```bash
python3 -m unittest discover -s demo/tests
python3 tools/check_repository.py
```

原生仿真需在专用测试目录构建仓库里的两个Nav2扩展，加载其overlay后运行：

```bash
export ROS_LOCALHOST_ONLY=1 ROS_DOMAIN_ID=187
unset CYCLONEDDS_URI
source /opt/ros/humble/setup.bash
source overlay/install/setup.bash
python3 tools/native_navigation_check.py --repeat 12
```

该程序使用真实 Nav2 控制器、代价地图、速度平滑、碰撞监视和门控节点。二维运动模型带有限加减速度。测试覆盖前进、倒车、临时挡路、反复停靠和断流，按当前停靠门限验收，并记录是否需要末端修正。仿真使用理想地图变换，结果保存在 `state/robustness/native/`。

50点位流程测试另用可控后端注入三次传感器中断和一次回充，核对同一点恢复、点位顺序以及最后完成状态。这是任务状态机测试，不是50个实体点位的运动验收。

### 双车定点到达与原地调向

普通巡航点和「50 个采集点」都先走可通行的路线，停稳后用原生 Spin 调整朝向。直线候选经过静态净空和实时路径检查，双车还要满足各自的通行许可。倒车能减少转角时可倒车。短时受阻会重新检查直线，再次失败则为原点位重新规划。确认到点所用的坐标始终是任务点。

需要调角时，直线交给转向的半径随预计转角连续收紧，45° 起使用 2.2 厘米。首次进入通常的停车半径后，过渡最多争取 1 秒。每辆车在当前进程中分别记录可信的左转和右转。30°～150° 的转动会用于估计车体中心在地图上的偏移。相近转角至少有四个不同点位，逐点留出预测仍可靠时，程序才沿来路和侧向修正入点位置，并重新检查整条线。修正受最终位置容差和可用路段长度限制。当前偏移与预测不符时，程序撤销该转向的历史标定。服务重启后从新观测重新学习。

车停稳后，原生 Spin 检查旋转扫过的车身。陀螺仪测量实际起转和转速，程序在同一转向内限速、预估余转并刹停。转向指令的纵向和横向速度都为零。车端连续核对不同时间戳的定位与雷达，实测位置误差 ≤5.5 厘米、朝向误差 ≤4° 才完成。只差朝向时保留位置，连续观测证实位置超界才重新移动。操作员停车优先，恢复通行沿用原轮次。

现场记录查看 `health.arrival.last_turn`。`requested_deg` 是请求的有符号转角，`gyro_at_release_deg` 是刹停时陀螺仪累计的转角，`before`、`after` 是转前和转后停稳的地图位姿。到点后在 `arrival_measurements.jsonl` 中可对照 `target`、`approach_aim` 和 `measured_map_pose`。经过多次调向的点额外保留 `first_terminal_turn`，可以核对第一次转过了多少、用了多久、车身中心偏向哪里。需要测实体误差时，在地面设置独立参照。

隔离 ROS 仿真使用上面的本机 ROS 环境。下列第一条命令使用合成底盘运行真实的控制器、Spin、速度平滑和碰撞保护。第二条用已有实车 JSONL 拟合起转延迟、制动和剩余转量，在留出的片段上比较三种控制。第三条在保存的地图上检查全部点对的直线净空，再改变假定的旋转中心，计算停稳后需要补位置的比例。

```bash
python3 tools/native_navigation_check.py --safety-only
python3 tools/fas_spin_benchmark.py state/logs/turn-a.jsonl state/logs/turn-b.jsonl \
  --output state/robustness/spin.json --repetitions 64
python3 tools/fas_station_replay.py --scene scenes/现场场景 --route state/north-u-50.json \
  --output state/robustness/stations.json state/logs/turn-a.jsonl state/logs/turn-b.jsonl
```

直线段使用 RPP，按距离、曲率和净空调整速度。原地段沿用 Humble Spin 的旋转碰撞检查。四个固定轮与地面有相对滑动，实际瞬时旋转中心会随地面和轮胎变化。[RPP 论文](https://arxiv.org/abs/2305.20026) · [Humble Spin 源码](https://api.nav2.org/nav2-humble/html/spin_8cpp_source.html) · [四驱滑移转向实验](https://babel.isa.uma.es/_utils/downloads/logdownloads.php?f=downloads%2Fjafma%2Fpapers%2Fmandow2007ekw.pdf&t=pdf&u=jafma)

## 实车验收与摆头诊断

当前足迹以 R550 Pro 四驱的车型尺寸为基准。换车或调整附件后，先核对轮子、支架和天线的完整外形，再测制动距离和扫描盲区。

短距离测试记录命令角速度、轮速角速度、陀螺仪和 AMCL 朝向。命令自身左右变化时，检查路线曲率、前视距离和定位跳变。命令基本直行而轮速或实体车偏转时，检查左右轮增益、轮径、轮距、地面打滑和电机响应。

换地面后，分别复测两车左右转的起转时间、零速指令后的实际余转和停稳后的车身中心偏移。只有相同方向的误差可复现时，才据实测调整转向制动或入点余量。轮趣 STM32 底盘手册第 4.5 节的四驱运动学假设地面摩擦充足、车轮不打滑。[轮趣 STM32 底盘开发手册](https://static1.squarespace.com/static/5e76e0c52a318c0c1a850442/t/629ecb41f4ccbd019090c07e/1654573983116/2.STM32%C2%A0Moving%C2%A0Chassis%2BDevelopment%2BManual_Mini%2BSerial_2021.04.01.pdf#page=39)

```bash
bash tools/record_navigation.sh
```

该命令只录制数据，不发车。到点另记录`arrival_measurements.jsonl`，包含目标、实测地图位姿、协方差和扫描一致性。用独立地面标记或测量设备验证实体误差，不能只看网页箭头。

依次验证直线往返、90°换边、前后近障碍、人员短时挡路、短暂雷达断流、重复点位、真实低电量回充与续作。每个点位记录外部实测误差与完成耗时。长时间和有人环境的可靠性以实车测试为准。

原生接口依据：[RPP反向行驶参数](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/controller_plugins/configuring_regulated_pp/)、[Humble碰撞监视参数](https://github.com/ros-navigation/navigation2/blob/humble/nav2_collision_monitor/params/collision_monitor_params.yaml)、[1.1.15碰撞时间判断源码](https://github.com/ros-navigation/navigation2/blob/1.1.15/nav2_collision_monitor/src/polygon.cpp)。Humble使用max_points；approach的静态判断包含等号，不能设置为0，否则无障碍也会停住。

# WS63 与 RSSI

本页用于固定基站的无连接广播采集。带舵机、停车后等待整轮结果的场景使用 [SERVO_CAR_2 定点联调](08-servo-car-v2.md)。

## 两端职责

| 设备 | 工作 |
|---|---|
| 固定 WS63 TX / Server | 100 ms 设置间隔的不可连接星闪广播 |
| 车载 WS63 RX / Client | 被动扫描，提取 RSSI、设备接收时间和序号，经 USB 串口上报 |
| RDK | 导航、实际地图位置、时钟对齐、逐条关联、过滤、保存、网页实测图 |
| 电脑或 RDK | 导出后做区域插值图 |

本版是单基站、无机械转动、无移相器。TX 和 RX 不建立无线连接。

## SDK 接入与烧录

把 `ws63/beacon_survey` 放到 SDK 的 `src/application/samples/bt/sle/beacon_survey`。父级 CMake/Kconfig 按 `ws63/sdk_integration/` 片段接入。

图形界面 SLE Sample 二选一：

- `R550 fixed RSSI beacon (no connection)`：固定基站。
- `R550 mobile RSSI broadcast receiver (no connection)`：车载接收，开启 `AT_SUPPORT_PLT`。

切角色后清理编译缓存，在 SDK 的 `src` 目录用原来的虚拟环境执行 `python build.py -c ws63-liteos-app -j8`，使用独立 BurnTool 烧录。

TX/RX 对应广播名 `R550_BC01`、地址 `52:35:35:30:00:01`。另做基站工程时保持一致，或同步修改 RX 的匹配条件。

固定 TX 放好后不移动。RX 用数据线接 RDK USB-A，提供供电和串口。HiHope 板在本车识别为 CH340K `1a86:7522`；串口优先使用 `/dev/serial/by-id/`。

## 配置采集路线

复制并编辑 `config/survey-route.example.json`。最外层是路段数组，每段是实际希望行驶的 `[x,y]` 路径坐标。去程和返程分段，宽处平行、窄处合流，坐标全部位于已知通道。

```bash
./kit stop
./kit scene survey room1 --bounds XMIN XMAX YMIN YMAX --route 自己的路线.json
./kit scene use room1
./kit nav
```

面板切到广播采集，串口 auto，应用连接，加载场景采集路线，开始巡航。`/rssi` 看实测色带。普通定时巡航切回定时模式即可，不依赖 WS63。

默认直线 0.08 m/s、弯道约 0.045 m/s，按约 10 cm 空间格统计；Client 持续采样，不在每格停靠。实际接收频率以设备和无线环境为准。

## 位置绑定与保存

RX 在广播接收回调记录时间；RDK 用新鲜设备心跳估计时钟偏移及漂移，再匹配定位时间。每条记录绑定实际地图位置、朝向和 map_id，不用导航目标坐标代替。

`raw.csv` 包括 RSSI、设备时间、主机时间、接收序号、实际位置、朝向、是否采用及原因。`points.json` 保存汇总格；`session.json` 保存坐标系、场景和基站说明。每轮独立保存，断线后自动尝试重新连接。

## 热力图

导出 ZIP 后：

```bash
./kit postprocess 数据.zip --out state/heatmap
```

结果有实测路径图、区域插值图、估计网格 CSV 和模型报告。强信号深蓝紫，弱信号浅青绿；RSSI -76 dBm 强于 -95 dBm。两图色标相同，标题分别为“区域RSSI”和“区域RSSI 插值估计”。

插值只覆盖场景已知自由空间，保留墙和禁区；区域颜色不是全部实测。换场地或改变基站、天线安装位置后重新采集。

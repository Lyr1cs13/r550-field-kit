# ESP32-C5 CSI 定点采集

车上放一块 C5 移动标签，由 RDK 的 USB 供电。场地固定四块 C5，其中一块通过 USB 数据线接采集电脑，作为主节点。四块固定板烧录同一方案的 `fixed_node`，车载板烧录配套的 `mobile_tag`。首次使用 `plan_fixed`。切换到 `plan_variable` 时，五块板和采集脚本一起换成对应版本。

## 准备固件

有匹配固件时可直接试采。首次烧录可使用方案包中两个角色的 `release_verified`，用 `flasher_args.json` 核对镜像和地址。本地准备好的副本在 `ESP32-C5采集联调/固件与采集脚本/`。

| 写入地址 | 镜像 |
|---|---|
| `0x2000` | `bootloader/bootloader.bin` |
| `0x8000` | `partition_table/partition-table.bin` |
| `0x10000` | 四块固定板用 `plan_fixed_anchor.bin`，车载标签用 `plan_fixed_tag.bin` |

在对应角色的 `release_verified` 目录执行以下命令。填写这块板实际出现的 COM 口和对应的 `$app`。示例使用 esptool 5。[乐鑫烧录手册](https://docs.espressif.com/projects/esptool/en/latest/esp32c5/esptool/flashing-firmware.html)

```powershell
python -m pip install "esptool>=5,<6"
python -m serial.tools.list_ports -v
$port = 'COM12'
$app = 'plan_fixed_anchor.bin'
python -m esptool --chip esp32c5 --port $port --baud 460800 --before default-reset --after hard-reset --no-stub write-flash --flash-mode dio --flash-freq 80m --flash-size 2MB 0x2000 bootloader/bootloader.bin 0x8000 partition_table/partition-table.bin 0x10000 $app
```

可变状态用对应角色目录下的 `plan_variable_anchor.bin` 和 `plan_variable_tag.bin`，固定节点接配套 FAS12 硬件。切换组态前保持原 NVS，便于重复实验使用相同的天线状态掩码。

## 先静止试采

1. 给四个固定节点和车载标签上电。用短数据线把固定主节点的 **USB-UART** 口接到电脑。试采时也可以让小车停在主节点旁，把该线接到 RDK 的 USB-A。串口为 3,000,000 baud、8N1。
2. 解压对方提供的方案包，保留 `fixed_node/tools/` 里的原始采集脚本和同目录模块。选刚插入的主节点串口。用完串口监视器或烧录工具后关闭它。

Windows PowerShell，在本工程目录执行。把脚本路径和 `COM12` 改成现场值。

```powershell
python -m pip install pyserial
python -m serial.tools.list_ports -v
$capture = 'D:/csi/plan_fixed/fixed_node/tools/capture.py'
python tools/c5_collector.py --plan fixed --script $capture --serial COM12 --probe
python $capture --port COM12 --seconds 30 --delay 0 --label fixed_smoke --point dock --output state/c5_smoke
```

在本机可用工程内的 `.venv/Scripts/python.exe`，将 `$capture` 指向 `../ESP32-C5采集联调/固件与采集脚本/plan_fixed/fixed_node/tools/capture.py`。

Ubuntu 或 RDK，在本工程目录执行。首次部署已安装 `python3-serial`。把示例串口换成刚出现的设备号。

```bash
python3 -m serial.tools.list_ports -v
capture="$HOME/csi/plan_fixed/fixed_node/tools/capture.py"
./kit c5-collector --plan fixed --script "$capture" --serial /dev/ttyUSB2 --probe
python3 "$capture" --port /dev/ttyUSB2 --seconds 30 --delay 0 --label fixed_smoke --point dock --output state/c5_smoke
```

看到匹配的 `STATUS` 后，确认试采发现 **4 个固定节点和车载标签**。结束时检查 `result.json` 的 `capture_ok` 和 `device_done`，在 `csi_packets.csv` 中筛选 `tx_role=tag`、`csi_valid` 为真，用 `rx_mac` 核对四个接收节点各自的有效包数。

## 在巡航面板使用

主分支包含 C5 定点采集。更新已有车辆时，按[开测操作顺序](11-start-and-verify.md)停车、部署源码，再运行 `./kit nav`。

1. 固定主节点留在场地，USB 接采集电脑。让 RDK 和电脑接入同一可互访网段。在电脑终端启动采集服务，`--listen` 填电脑在小车网内的 IP。Windows 用 `ipconfig`、Linux 用 `ip -br addr` 核对。

```powershell
python tools/c5_collector.py --plan fixed --script $capture --serial COM12 --listen 192.168.0.210 --seconds 30
```

Linux 下同样参数可用 `./kit c5-collector`。若服务和巡航面板都在 RDK 上做近距离联调，地址用 `127.0.0.1`。多人同时试验，或附近有多个 C5 标签时，用 `--tag-mac aa:bb:cc:dd:ee:ff` 指定车载板的实际 MAC。

2. 把采集电脑自动生成的 `state/c5.token` 复制到 RDK **当前巡航工程**的 `state/c5.token`。例如工程安装在 `~/lab_cruise_ws` 时，在采集电脑运行以下命令。

```bash
ssh wheeltec@192.168.0.100 'mkdir -p ~/lab_cruise_ws/state'
scp state/c5.token wheeltec@192.168.0.100:lab_cruise_ws/state/c5.token
```

RDK 终端运行以下命令。配置命令连通后才保存服务地址。连接失败时核对采集电脑 IP、电脑防火墙的 TCP 8791 和两边的 token。

```bash
cd ~/lab_cruise_ws
chmod 600 state/c5.token
./kit c5-config http://192.168.0.210:8791
```

3. 打开已部署新版的巡航面板，确认定位并设两个普通导航点。在“采集联动”中启用 **每站采集 ESP32-C5 CSI**，点“应用 / 重新连接”。看到 C5 就绪后，先用一个点的“前往”核对停稳与保存，再开始多点巡航。

| 使用方式 | 面板设置 |
|---|---|
| 只用 C5 | 定时停留（原有模式）＋勾选 C5。停留由采集结果决定。 |
| C5 与 WS63 旋转定点同时采 | 旋转定点采集（SERVO_CAR_2）＋勾选 C5。两边都完成才离站。 |
| 普通巡航或只用 WS63 | 取消勾选 C5，照常选择原模式。 |

可变状态联调时，从对应包取 `fixed_node/tools/capture.py`，采集服务参数改为 `--plan variable --groups 16 --seconds 120`。整轮采集改为 `--groups 4096 --seconds 3600`。`--seconds` 是采集上限，固件完成指定组数并确认闭合后即可提前结束。

## 取数据

- **采集电脑**的 `state/c5_captures/<visit_id>/` 保存 `visit.json`、`receipt.json`、日志，以及原脚本写出的 `capture/` 目录和原始数据。可变状态分析用 `csi_packets_confirmed.csv`，再按有效 CSI 筛选。回执记录所用标签、锚点有效包数和原始会话编号。
- **巡航面板**点“导出 C5 停靠位姿与地图”。ZIP 含 `visits/` 和对应版本的地图。每站记录实际 `x、y、yaw`、坐标系、到站 UTC 和 C5 会话 `(root_mac, root_boot, run)`。位置单位为米，朝向单位为弧度。以 `released_utc` 确认巡航已处理本轮完成回执。
- 与 WS63 并采时，同时导出“历史旋转定点记录”，按 `visit_id` 对齐同一次停车。两套硬件的逐包时钟仍各自保留。

## 停止与复测

暂停巡航时当前采集可以继续保存，点“继续”后才离站。点“停止任务”会请求主节点结束当前采集并保留部分文件。连接中断、采集失败或定位失效时，小车保持停车。检查 `capture.log` 和面板提示，恢复串口或连接，再应用采集设置并重测该点。USB 重插导致设备号变化时，先核对设备号再启动采集服务。

# 从小车开机到实车验收

## 工程和入口

虚拟机正式工程是`/home/wheeltec/lab_cruise_ws`。日常演示时，打开小车电源，让电脑外接 Wi-Fi 连上小车网络，再双击虚拟机桌面的「巡航演示」。入口通过 SSH 启动车端导航，并打开虚拟机本地面板。车端在线后，面板会自动显示车辆状态和现场地图。

面板打开后核对定位，再选择单点或开始巡航。车端连接暂未建立时，面板可显示已保存的现场地图。

## 第一次开测顺序

1. 清出一小段测试区域，确认急停或手柄停车可用。把车放在已标定的原充电桩，方向与标桩时一致；确认充电桩供电。若充电桩已移动，须重新标定，不能直接套用旧桩位。
2. 打开小车电源，等待RDK启动和小车网络出现。电脑外接Wi-Fi连接小车网络，保持VMware的车网桥接网卡连接；NAT网卡保留给虚拟机上网。本机虚拟机当前车网地址为192.168.0.250，小车地址为192.168.0.100。
3. 在虚拟机终端确认连接：

```bash
ssh r550 'hostname; uname -m'
```

预期能登录wheeltec账户，架构为aarch64。首次出现主机指纹提示时核对设备；网络不通先处理连接，不进入运动测试。

4. 首次部署前关闭车端旧导航。进入小车终端：

```bash
ssh r550
cd ~/lab_cruise_ws
if [ -f kit ]; then ./kit stop; else bash demo/stop_demo.sh; fi
exit
```

确认实体车停稳。部署程序也会检查底盘、导航和建图进程，有运行中的程序就拒绝覆盖，不会一边行驶一边更新。

5. 需要更新车端源码时，在虚拟机执行以下命令。

```bash
cd ~/lab_cruise_ws
python3 tools/deploy_robot.py
```

程序打包源码、上传、验证哈希、备份被替换的源码、保留车端地图/桩位/历史点位/采集数据，然后在小车上编译ARM控制器并执行导航依赖检查（doctor --navigation）。现有vehicle.yaml和endurance.yaml保留。若旧工程没有active_scene记录，使用车端原地图建立记录，不拿虚拟机地图覆盖。

依赖齐全时不运行apt；缺少依赖时需要小车联网，并可能要求输入车端sudo密码。虚拟机已经编译过x86控制器，但该二进制不能给ARM小车使用。部署成功不会启动任务，也不会发车。

6. 双击虚拟机桌面的「巡航演示」。连接成功后页面会显示车端状态。启动日志保存在虚拟机工程的 `state/logs/vm-demo-launch.log`。

7. 核对地图、桩位、车头、红色雷达与现场墙线。确在原桩时使用「车在桩位：初始化」，在其他位置时按实际位置设置定位。对齐后确认定位。
8. 暂时选“定时停留”模式，不启用WS63或C5采集。关闭“完成后回充”，先验证底盘。准备独立地面标记和尺子，不能只根据网页坐标判断2cm精度。
9. 在车端另开一个终端记录日志：

```bash
ssh r550
cd ~/lab_cruise_ws
source /opt/ros/humble/setup.bash
bash tools/record_navigation.sh
```

该窗口保持运行，测试结束按Ctrl+C保存。到点记录还会自动写入`demo/data/ros/arrival_measurements.jsonl`。

## 按顺序验证，不直接开始50点长任务

| 顺序 | 如何操作 | 通过条件 |
|---|---|---|
| 1.静止与定位 | 保持停车观察30秒，核对车头和墙线；检查当前足迹覆盖轮子、支架和天线 | 没有轮子自转、明显雷达错位或车姿漂移。若出现自身天线回波，先处理安装或核对既有精确过滤配置，不能随意扩大屏蔽区域 |
| 2.短直线前进 | 空旷直线设置约0.5m外的点，目标朝向与当前车头一致，单点前往 | 平稳减速停下。记录地图误差和独立实测误差；位置目标≤2cm、朝向目标≤1° |
| 3.同朝向倒车 | 在刚才起点附近设置目标，朝向仍与现在车头相同，确认后方完整可见且清空 | 直接倒车返回，不先掉头180°；同样测量误差 |
| 4.换边和转向 | 选有足够转身空间的侧向点，到达朝向仍设统一方向 | 行驶时允许转向，到点后恢复统一朝向。四驱差速不能横移，不能要求侧向换边全过程车头不转 |
| 5.前后障碍停车 | 用雷达能检测到的障碍物，在车前/车后足够距离处挡住路线；不要用身体做碰撞测试，不要等接触才撤除 | 车在接触前停车或绕开。移开障碍后恢复原目标，不能跳过点位；不满足则停止后续人员测试 |
| 6.短时通路阻塞 | 在宽走廊可绕行处放障碍，再在无法绕行但有充分停车距离的位置临时封路，保持数秒后移走 | 分别验证绕行和停车等待后继续；当前点位保持不变 |
| 7.重复精度 | 同朝向两个点往返10次，逐次记录实体误差 | 所有到点均达到约定门限，没有逐轮累积漂移。超差就留存日志分析，不放宽门限冒充通过 |
| 8.实际回充 | 完成上述测试后，在桩前空间正常的条件下按“主动回充” | 导航至桩前、红外贴合、稳定充电且轮子停下，页面才确认回充完成 |
| 9.回充后续作 | 先核实电池型号、低电量电压、充电恢复电压与持续时间；再配置endurance.yaml并重启服务 | 低电量保存当前进度，回充满足条件后继续原待完成点位，不重复顶桩、不跳站。当前默认未启用，不能填写猜测的电压 |
| 10.50点和长时间 | 前面全部通过后，先无采集跑路线，再加入真实采集；人数和任务长度逐步增加 | 点位顺序、停靠朝向、采集完成、回程和定位记录都正确 |

断流和心跳失效已做无车原生故障注入。现场不要在运动中随意拔掉雷达、底盘串口或电源来复现；如需硬件故障测试，应另设隔离场地和独立停车保护。

## 异常时如何处理

普通临时挡路会保留目标并重试。定位异常会停车，符合扫描一致性和稳定条件后自动恢复；恢复不了则保持暂停。不要直接把实车搬回旧位置后按继续，应重新核对并初始化实际定位。明确停止可用面板“停止”或车端`./kit hold`；它会取消当前任务，因此不要把它当作普通“暂停”。

程序意外重启后，面板“载入未完成点位”只加载记录，不发车。核对定位和采集设置后再开始；尚未确认完成的当前站可能重新采集。主动停止会清除续作记录。

## 改进与目前能说明的效果

- 直线前进/倒车使用独立控制器，减少为了行驶方向而反复掉头；批量统一朝向可以避免逐点输入。
- 普通点位、离桩和回桩受阻后停车重试，避免一次失败直接结束任务或跳过普通采集点。
- 普通停靠使用 4 cm 和 4° 的停稳判定，双车 FAS 使用 3° 朝向门限。实体误差通过地面标记独立测量。
- 独立速度门控检查雷达和控制许可；雷达断流、过期帧、无效帧、控制心跳失效均做过原生测试。回充监督丢失只发送关闭红外模式指令，绝不自行启动回充。
- 定位协方差和扫描一致性异常会停车，停稳复核后才恢复；不能据此保证二维雷达看不见的低障碍或重复走廊误定位一定可自动解决。
- 保存任务进度、真实地图位姿及到点误差；增加充电续作策略，默认等待电池实测后启用。

回归测试覆盖部署备份、场景保留、坏包拒绝和传感器中断后的巡航续作。原生仿真覆盖直行离桩、低速倒车、遇障停车和雷达断流。精度与长时间运行按上面的顺序实车验收。

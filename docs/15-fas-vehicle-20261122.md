WS63 用 BurnTool 选择相应的 `.fwpkg`。C5 镜像已包含引导程序、分区表和应用，选 ESP32-C5，使用地址 `0x0` 烧录两次。C5 镜像用本机 ESP-IDF 5.5.4 构建，交接包建议使用 5.5.5。

每车用两根数据线把两块板接入本车 RDK。用 WS63 启动日志校验 `DUAL_SERVER_READY id=1` 或 `id=2`，用 C5 启动日志的 `V,sender` 或基站发现结果核对完整 MAC。核对完成后运行 `ls -l /dev/serial/by-id /dev/serial/by-path`，记录每块板的固定 USB 路径。

## RDK 配置

交付包中的 `rdk-connected.patch` 可从巡航仓库根目录使用 `git apply --check rdk-connected.patch` 检查，再用 `git apply rdk-connected.patch` 应用。补丁仅涉及 `demo/fas_car.py`。

在两车各自的实车巡航工程中更新 `state/fas_robot.json`。下面是 A 车配置结构，B 车使用 `"car": "B"` 和本车实际串口及 MAC。地图 ID 读取本车 `state/active_scene.json`。

```json
{
  "car": "A",
  "map_id": "现场地图 ID",
  "motion_only": false,
  "ws63_mode": "connected",
  "ws63_device": "/dev/serial/by-path/实际WS63路径",
  "c5_device": "/dev/serial/by-path/实际C5路径",
  "c5_mac": "本车 C5 的真实 STA MAC"
}
```

更新和重载前先结束并释放原实验。使用正常巡航入口启动，核对车端实验状态的 `ws63_mode` 为 `connected`、`usb` 为真、`tx` 与实际身份一致。车端在该模式确认 USB 枚举和停车许可。星闪连线、RSSI 查询和 C5 发包窗口由基站控制，基站静止试采负责核验实际无线身份。

## 基站交接

现有网页可以连续扫描停着的两台车。它在首次命中或扫描完 4096 态后直接从状态 0 重开，两频段独立运行。自动采集需要基站按 PC 指定的状态或状态列表测量，结束后等待 PC，且关闭窗口可确认。仅在网页收到 `RF_ROUND` 后发送停止命令会与下一轮竞态。

车端调度已经使用 `FAS_PAIR_1`，接口见 [基站主机接口](13-fas-dual-radio.md#基站主机接口)。现有调度入口按**一个状态一次请求**工作。若要一次停车批量扫多个状态，基站和调度均需实现批量接口。基站适配层应为每个请求确认实际状态字，输出窗口内 A/B 算术均值和样本数，并保留逐态原始数据。ESP 和 WS63 都按采样编号及状态绑定，配对后才能应用 6 dB 判据。

## 静止验收及续采

先验 USB、A/B 身份、两路充足样本、收发与状态一致性，再用几组状态核对两车到位、关窗后回充、恢复原实验库的完整流程。正式运行必须使用持久化 SQLite 路径。低电时关窗，充电与定位恢复后重测未完成窗口。现有 `--unattended` 参数适用于行驶演练，射频采集闭环需通过基站接口和两车实测验收。

50 点最多形成 2450 个有序位置对。搜索上限默认每态 12 对。若要对某状态给出“在候选范围内未找到”，必须在该状态取得全部允许位置对的有效测量。样本不足、通行失败和预算用尽都应保留待办或对应记录。
